# UI_DESIGN.md — AWS 서비스 그룹 관제 WPF UI/UX 확정 설계

> 기준: 사용자 설계 협의 질문 1~100. **[확정]**은 사용자 선택, **[설계 기본값]**은 미세 UX 구현 가이드, **[Backlog]**는 추후 범위이다. 구현은 WPF XAML/MVVM으로 직접 진행하며 Figma를 사용하지 않는다. `REQUIREMENTS.md`의 기능과 `DEVELOPMENT_PLAN.md`의 개발 단계를 함께 따른다. 화면 명세가 곧 모든 기능의 Phase 1/Day 1 완료를 뜻하지 않는다.

## 1. 전역 화면 구조

- **[확정]** 단일 메인 창, 왼쪽 메뉴 전용 사이드바, 상단 AWS 연결 바, 가운데 페이지, 하단 **전역 작업 진행 패널**. 그룹 목록을 사이드바에 항상 펼쳐 두지 않는다.
- **[확정]** 기본 다크 테마. 현대적인 대시보드 디자인에 산업용 관제에 적합한 정보 밀도를 결합한다.
- **[확정]** 최초 창 크기 1440×900, 최소 1280×720, 창 크기 조절 지원. 메뉴 체계 자체를 반응형으로 바꾸지 않는다. 창 크기·위치·최대화 여부를 저장/복구하며 모니터 변경 시 화면 밖으로 나가지 않도록 복원 위치를 보정한다.
- **[확정]** 한국어 UI/안내 문구, AWS 고유 식별자·상태 코드 영어 표기.
- **[확정]** 상단에 연결 여부, 활성 AWS 프로필 이름, **전체** AWS 계정 ID 표시. 리전은 그룹별 정보이므로 상단 전역 리전으로 표시하지 않는다.
- **[확정]** 사이드바 메뉴: `대시보드`, `AWS 연결 관리`, `그룹 만들기`, `작업 기록`, 하단 `설정`. 그룹 관리는 그룹 상세 헤더의 `설정`에서 이동한다.
- **[확정]** 앱을 시작하면 항상 대시보드. 등록 그룹이 없으면 첫 등록을 안내하는 빈 상태를 표시한다.
- **[설계 기본값]** 주요 내용은 ScrollViewer로 스크롤, 긴 데이터 표는 DataGrid 자체 스크롤·열 너비 조절 지원. 버튼에는 텍스트와 아이콘을 함께 사용하고 키보드 포커스를 확인한다.

### 1.1 화면 트리

```text
메인 창
├─ 전역 상단 바: 연결 상태 / 프로필 / 전체 계정 ID
├─ 사이드바: 대시보드 / AWS 연결 / 그룹 만들기 / 작업 기록 / 설정
├─ 본문
│  ├─ 대시보드: 그룹 카드
│  ├─ AWS 연결 관리
│  ├─ 그룹 생성 마법사(5단계) / 등록 성공
│  ├─ 그룹 상세: 요약·전체 제어 / EC2 / RDS / S3 / 로그
│  ├─ 그룹 관리: 기본 정보 / 리소스 관리 / 시작 순서 / Health / 로그 설정
│  ├─ 작업 기록
│  └─ 설정
└─ 전역 하단 제어 진행 패널: 요약 / 펼친 단계 내역 / 최근 완료 5건
```

## 2. 상태 표시 및 피드백의 공통 규칙

- **[확정]** 상태는 **색 + 아이콘 + 문구**를 함께 표시한다. Running=녹색, Stopped=회색, 전환 중=파랑, 오류=빨강, Unknown=노랑. AWS Running과 애플리케이션 Health 정상은 동일하지 않다.
- **[확정]** 오류는 해당 화면/영역의 인라인 배너, 성공은 일시적 토스트, 위험 제어·삭제·프로필 변경·연결 해제 및 변경사항 저장은 확인 모달. 제어 실패는 하단 진행 패널에 남긴다.
- **[확정]** 알림 센터/알림 영구 기록은 만들지 않는다. 제어 이력은 별도 작업 기록에서 관리한다.
- **[확정]** 조회 중 기존 마지막 정상 값을 유지하며 작은 새로고침 아이콘을 표시한다. 최초 조회 중에는 `조회 중…`으로 표시한다.
- **[확정]** 조회 실패는 마지막 값에 **`이전 상태`**, **`조회 실패`**, **마지막 정상 조회 시각**을 함께 명시한다. 이전 값이 없으면 `상태 확인 불가`를 사용한다. 경고 아이콘 툴팁에 짧은 오류 원인, 상세 화면에 자세한 원인을 표시한다.
- **[확정]** 인증 만료/실패 시 상단 바 및 현 화면 배너에 오류와 `AWS 연결 관리` 이동 링크 제공, 현재 화면을 자동 이탈시키지 않는다. 치명적 인증 실패 후 자동 API 조회는 재연결 전까지 중단한다. 일시적 조회/네트워크 오류는 다음 주기에 재시도하고 서비스별 권한 오류는 서로 독립적으로 표시한다.
- **[설계 기본값]** 성공·실패·빈 데이터·계정 불일치·권한 없음·미연결·로드 중 상태를 별도로 ViewModel 상태로 둔다. 조회 실패를 Stopped/빈 목록으로 오인시키지 않는다.

## 3. AWS 연결 관리 화면

- **[확정]** 한 시점에 앱 전체 **활성 AWS 프로필 하나**. 그룹 상세에서 프로필을 바꾸지 않는다. 여러 그룹에 프로필을 동시에 연결하는 기능은 [Backlog].
- **[확정]** 로컬 프로필 ComboBox, `프로필 목록 다시 읽기`, `연결`, `연결 상태 확인`, `연결 해제` 버튼 제공. 그룹 리전 선택은 **연결 화면이 아닌 그룹 생성 마법사**에서 한다.
- **[확정]** 마지막으로 선택한 프로필만 로컬 설정에 저장. 실행 직후에는 **자동 인증/연결 없음**, 명시적 `연결` 클릭 후 AWS STS 호출. 로그인/연결 상세에 프로필 이름, 전체 계정 ID, Caller ARN, 상태, 마지막 인증 확인 시각을 표시하며 자격 증명은 절대로 노출하지 않는다.
- **[확정]** `연결 상태 확인`은 수동 STS `GetCallerIdentity`; 자동 STS 주기 확인은 수행하지 않는다.
- **[확정]** 다른 프로필로 전환하거나 연결을 해제할 때 확인 모달 제공. 프로필 전환 시 **새 프로필 검증 성공 후** 활성 프로필을 교체하고 실패하면 원래 연결 유지한다.
- **[확정]** 제어 작업 중에는 프로필 전환 및 연결 해제를 막는다. 다른 AWS 계정에 등록된 그룹은 로컬 세부정보 열람은 가능하나 AWS 조회·제어 버튼이 비활성화되며 계정 불일치 배너를 띄운다.

## 4. 대시보드

- **[확정]** 서비스 그룹 카드형. 기본 1440px에서는 **3열**, 좁은 창은 **2열**, 카드 최소 너비 확보. 개별 리소스 이름까지 카드에 펼치지 않는다.
- **[확정]** 카드 콘텐츠: 그룹명, 그룹 리전, EC2/RDS/S3별 개수 및 기본 상태, 마지막 정상 조회 시각. 그룹 전체를 합친 단일 Health 점수/정상 판정은 사용하지 않는다.
- **[확정]** 카드 클릭=그룹 상세 이동. 카드에 시작/중지 단축 제어 버튼을 두지 않는다.
- **[확정]** 이름 부분검색(대소문자 무시), 정렬 ComboBox `이름(기본) / 최근 생성 / 최근 수정`. 생성·수정 시각은 로컬에 저장한다.
- **[확정]** 전체 그룹의 기본 EC2/RDS 상태와 S3 조회 가능 여부를 **30초마다 자동 조회**. 현재 프로필과 계정이 다른 그룹 또는 AWS 미연결 시 자동 조회 제외. CloudWatch 상세 지표는 활성 상세 그룹 중심.
- **[확정]** `전체 새로고침` 및 **카드별 새로고침** 제공. 중복 호출을 억제하고 가능한 범위에서 최근 조회 결과를 재사용한다.
- **[확정]** 카드 갱신 중 기존 정상 상태를 유지하고 작은 로딩 표시, 조회 실패 시 이전 상태·오류 표시·툴팁, 최초 조회 실패면 `상태 확인 불가`.
- **[확정]** 등록 그룹이 없는 대시보드에 그룹 만들기 안내 및 이동 동작 제공.

## 5. 그룹 생성 마법사 및 등록 완료

1. **그룹 정보:** 그룹명, 활성 AWS 계정 확인, 그룹 리전 선택 ComboBox(예: `서울 (ap-northeast-2)`, 기본 서울). 그룹 이름은 trim 후 1~50자, 한글·영문·숫자·공백·`- _ .`만 허용, 대소문자 무시한 전역 중복명 금지. 그룹 리전은 생성 후 변경 불가.
2. **서비스 선택:** EC2/RDS/S3 선택 카드. 선택하지 않은 서비스는 API 조회하지 않는다. 비어 있는 그룹도 경고 후 허용한다.
3. **리소스 선택:** EC2/RDS/S3 각각 탭, 체크박스 선택 + 합계 요약. EC2 열 `이름 / Instance ID / 유형 / 상태`; RDS `DB Identifier / 엔진 / 상태`; S3 `버킷 / 리전`. S3는 그룹 리전과 다른 버킷도 선택 가능하고 버킷의 실제 리전을 저장한다. 타 그룹에 등록된 리소스 안내 및 중복 연결 금지. 테이블 헤더 정렬(오름/내림), AWS 조회 페이지네이션 및 WPF DataGrid 행 가상화. 정렬 후 선택 상태 유지.
4. **시작 순서:** EC2/RDS를 혼합한 순서 목록, 드래그 앤 드롭과 위/아래 버튼 모두 지원. 중지는 역순이며 S3는 대상에서 제외.
5. **검토 및 등록:** 이름·계정·리전·서비스별 연결 자원·시작 순서·빈 그룹 여부 재확인. **최종 등록을 누르기 전에는 JSON 저장하지 않는다.**
- **[확정]** 미저장 변경사항이 있을 때 중단/이탈 시 확인창 표시. 이전/다음 버튼과 단계 표시.
- **[확정]** 등록 후 **성공 전용 화면**에 `그룹 상세 열기`, `대시보드로 이동` 버튼 제공.
- **[확정]** 그룹 내부 식별자는 이름과 독립적인 안정적 고유 ID(GUID 등)를 사용한다.

## 6. 그룹 상세 관제

- **[확정]** 헤더: 그룹명, 계정 ID·리전, 기본 상태 요약, 새로고침, **`설정`** → 그룹 관리 전용 화면.
- **[확정]** 상단에 **그룹 시작/중지 전용 제어 섹션**. 그룹 제어 전 반드시 대상·실행순서와 비용/중단 영향을 확인하는 모달 표시.
- **[확정]** `EC2 | RDS | S3 | 로그` 메인 탭과 별도의 전체 자원 조합 요약. 서비스별 테이블은 이름/식별자 검색과 헤더 정렬, 선택 리소스 하단 상세 패널로 구성. 테이블과 상세 패널 사이 WPF GridSplitter로 높이 조절.
- **[확정]** 개별 시작/중지/재부팅 버튼은 **하단 상세 패널에만** 배치. S3는 제어 기능 없음. 하단 패널에는 `기본 정보 | 모니터링` 등 역할별 탭.
- **[2026-10-21 확정]** 이번 개별 제어에서는 EC2/RDS/S3 탭·이름/식별자 검색·선택 자원 기본 정보와 GridSplitter를 구현한다. S3 선택 시 제어 버튼은 숨긴다. 로그·모니터링·Health는 기존 후속 단계에서 제공한다.
- **[2026-10-21 확정]** EC2 재부팅은 `요청 접수 · 재부팅 완료 미확인`으로 표시한다. 제어 상태 확인 간격은 EC2 5초·RDS 15초, 제한시간 입력은 EC2 1~60분·RDS 1~120분(기본 10분·30분)이다. 제어 중 연결 재확인도 연결 세대 변경을 피하기 위해 차단한다.
- **[확정]** EC2 목록 및 상세 기본 정보에 앱 Health 요약, 상세의 Health 하위 탭에 최신 및 최근 10회 점검 이력 표시.
- **[확정]** 그룹 전체 새로고침과 서비스 탭별 새로고침을 구분하고 동일 API 중복 실행을 피한다.
- **[확정]** 다른 계정 그룹은 로컬 데이터 열람만 허용하고 AWS 동작은 차단; 안내 배너 및 AWS 연결 페이지 이동 제공.

## 7. 그룹 관리 전용 화면

- **[확정]** 탭: `기본 정보 | 리소스 관리 | 시작 순서 | Health | 로그 설정`.
- **[확정]** 저장/취소 버튼은 화면 하단. 모든 탭에서 변경을 메모리에 임시 반영한 뒤 `변경사항 저장` 클릭 시 **기존값/변경값 비교 확인 모달**을 보여주고 JSON을 갱신. 이탈 시 미저장 변경 경고.
- **[확정]** 리소스 추가는 그룹 생성과 **동일한 리소스 선택 컴포넌트** 재사용. 추가 자원의 EC2/RDS 시작 순서도 설정 대상이다.
- **[확정]** 리소스 연결 해제는 체크박스 다중 선택으로 가능하며 AWS 자원은 삭제하지 않는다. 변경은 저장 전 임시 상태.
- **[확정]** 그룹 삭제 시 간단한 확인 모달 표시. 로컬 그룹 정보만 삭제하며 AWS 자원은 유지한다.
- **[2026-10-21 우선순위 변경]** 그룹 관리 전체 화면 구현 전 그룹 상세 헤더에 `그룹 삭제` 버튼을 먼저 제공한다. 확인창에 그룹명과 AWS 자원 유지 안내를 표시한다. 취소·저장 실패 시 현 화면과 그룹을 유지하며 저장 성공 후 대시보드로 이동한다. 빈 그룹·미연결·계정 불일치 상태에서도 삭제 가능하다. 그룹 관리 화면 완성 시 해당 화면에 통합한다.
- **[확정]** 이름 변경 가능, 그룹 리전 변경 불가능. AWS 전역 활성 프로필 변경은 `AWS 연결 관리` 화면에서만 수행한다.

## 8. 전역 제어 진행 패널·실행 기록

- **[확정]** 화면을 전환해도 한 번 시작된 AWS 제어는 계속 진행한다. 화면 하단 고정 요약 바를 클릭/펼치면 단계별 내역 확인. 완료된 작업 최근 약 **5건**을 최근순으로 표시.
- **[확정]** 앱 전체에서 **동시 제어 작업 1개만** 허용(그룹 전체 제어 및 개별 제어 포함). 충돌 명령 차단. 다중 제어는 [Backlog].
- **[확정]** 진행 단계: `대기 → 명령 전송 → AWS 요청 접수 → 목표 상태 대기 → 완료 / 실패 / 시간 초과 / 사용자 취소 / 미실행` 등으로 구별.
- **[확정]** EC2 목표 `Running/Stopped`, RDS 목표 `Available/Stopped`에 실제 도달한 후 다음 단계로 이동. 그룹 시작은 순차, 그룹 중지는 역순. Health 정상은 완료 조건이 아니다.
- **[확정]** 실패·시간 초과는 Fail-Fast, 이후 단계 미실행, 자동 롤백 없음. 이미 변경된 AWS 상태는 유지한다.
- **[확정]** `남은 작업 취소` 버튼과 확인 모달 제공. AWS에 이미 전달한 명령은 되돌리지 않으며 현재 단계 결과를 확인한 뒤 이후 단계를 취소한다.
- **[확정]** 제어 중 종료 시 경고를 표시하고 사용자가 종료를 선택할 수 있다. 그 경우 남은 단계는 실행되지 않으며 이미 제출된 AWS 명령은 서버에서 진행될 수 있다.
- **[확정]** 상태 전환 제한 시간 기본값 **EC2 10분, RDS 30분**, 설정에서 각각 변경 가능. 시간 초과는 프로그램이 목표 상태 도달을 확인하지 못했다는 뜻이며 AWS 작업의 최종 실패 판정으로 사용하지 않는다.
- **[확정]** 작업 기록 화면은 SQLite에 저장된 **전체 작업/리소스별 단계** 이력을 조회·검색·필터. 기록 보존 정책은 7일 / 30일(기본) / 무기한, 시작 시 만료 기록 삭제.
- **[설계 기본값]** 작업 확인 모달에는 프로필·계정·그룹·실행 대상·명령·순서를 표시한다. 실행 단계별 실제 AWS 요청과 결과를 식별 가능하게 기록한다.

## 9. CloudWatch 상세 그래프

- **[확정]** 그룹 상세 하단 모니터링에서 시간 범위 `1시간(기본) / 3시간 / 12시간 / 24시간`, 자동 갱신 **5분**.
- **[확정]** 그래프 패널은 기본 2열, 상세 영역이 좁으면 1열. 차트 위에 **가장 최신 측정값**을 크게 표시하고 AWS 측정 시각·단위 제공. 점 툴팁에 해당 시각 값 표시.
- **[확정]** EC2/RDS CPU와 RDS DB 연결 수는 선 그래프, EC2 네트워크 송신·수신은 구별되는 두 계열, S3 저장량/객체 수는 일 단위 데이터 특성 반영. 측정값 없음은 0이 아닌 `데이터 없음`.
- **[확정]** 오픈소스 WPF 차트 라이브러리를 사용한다. **[구현 시 검토]** LiveCharts2/OxyPlot 등 후보의 WPF·MVVM 호환성, 라이선스·유지보수를 확인해 결정한다.

## 10. 애플리케이션 Health UI

- **[확정]** 그룹 관리 `Health` 탭에서 EC2에 앱 여러 개 등록. 항목별 이름, 인증 없는 HTTP/HTTPS URL, 기본 2xx 판정 또는 선택적인 본문 JSON/status `UP` 검사 규칙.
- **[확정]** 비정상 응답/본문 불일치는 즉시 `비정상`, 네트워크/타임아웃은 별도 `연결 실패` 구분. 일반 30초 주기, 수동 앱별/전체 검사 가능하며 중복 요청 방지.
- **[확정]** Health HTTP 타임아웃 설정: `3초 / 5초(기본) / 10초 / 15초`.
- **[확정]** 최신 결과와 최근 10회 점검 이력은 앱 실행 중 메모리에서만 유지하며 종료 시 폐기. EC2 목록·기본 정보에 요약, 상세의 Health 탭에 최근 10회 표시.
- **[Backlog]** 인증이 필요한 Health 엔드포인트 지원.

## 11. CloudWatch Logs UI

- **[확정]** 그룹 관리 `로그 설정`에서 로그 그룹 여러 개 연결; 그룹 상세의 **`로그` 메인 탭**에서 한 번에 하나를 선택해 조회. 여러 로그 그룹 통합 조회는 [Backlog].
- **[확정]** 기본 모든 로그 스트림에서 조회하며 특정 스트림을 필터 선택 가능. 조회 기간 `1시간(기본) / 24시간 / 7일 / 직접 시작·종료 시각`.
- **[확정]** AWS에서 조회한 최근 100건에 클라이언트 키워드/레벨 필터 적용. 별도의 **명시적인 서버 측 AWS 검색**도 제공.
- **[확정]** 상단 표 `시각 / 레벨 / 메시지 미리보기`; 선택 로그 원문·스택 트레이스·복사는 하단 상세 패널. WPF GridSplitter로 높이 조절.
- **[확정]** 각 그룹의 로그 조회 조건은 앱 실행 중 RAM에만 기억하고 재실행 시 초기화. 서버 로그 수집 설정은 앱이 자동 구성하지 않는다.

## 12. 설정 화면 및 로컬 저장 오류

- **[확정]** 설정: 제어 작업 기록 보존 `7일 / 30일(기본) / 무기한`, Health HTTP 타임아웃 `3/5/10/15초(기본 5초)`, AWS 상태 전환 타임아웃 **EC2 기본 10분 / RDS 기본 30분** 각각 변경 가능.
- **[확정]** 로컬 JSON: 그룹, 리전, AWS 계정 ID, 리소스, 순서, Health/로그 연결, 앱 설정, 마지막 선택 프로필, 창 상태. 로컬 SQLite: 작업 전체 이력/리소스별 제어 단계.
- **[확정]** 시작 시 JSON 파싱 또는 필수 값 검증 실패 시 오류 안내 후 종료; 자동 초기화·자동 백업 복구 및 손상 파일 덮어쓰기 금지. 사용자가 수동 복구한다.
- **[설계 기본값]** 타임아웃 직접 변경값은 양의 정수 분이며, 지나치게 짧거나 큰 설정값은 UI에서 검증한다. 구체 허용 범위는 구현 단계에서 결정하며 임의로 확정 요구사항으로 취급하지 않는다.

## 13. 검증 체크리스트 및 단계 구분

- Phase 1 Day 1: 셸/대시보드 최소형, 명시적 AWS 연결, 5단계 그룹 생성, 등록 완료, JSON 저장·복원, 서비스별 읽기. 
- Phase 1 Day 2: 확인 모달, 전역 제어 단일 실행, 시작/중지 순차 제어와 실제 목표 상태 확인, 실패/취소/타임아웃 및 하단 패널 최소형.
- Phase 2: 그룹 관리의 편집 탭 완성, SQLite 작업 기록 검색·보존, 정기 자동 갱신 고도화, CloudWatch 상세 그래프, Health, 로그 및 UI 마감. Phase 1에서 필요한 안전 정책은 Phase 2로 미루지 않는다.
- Phase 3 [Backlog]: 그룹별 동시 AWS 프로필, 동시 제어, 로그인 Health, 로그 그룹 통합 검색, 그 밖의 고급 기능.
