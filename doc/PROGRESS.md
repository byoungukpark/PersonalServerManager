# 개발 진행 현황

> 기준일: 2026-10-21 (Asia/Seoul)
> 확인 기준: 2026-10-21 사용자 수동 검증 보고와 현재 구현·빌드·로컬/Mock 검증. Day 2 개별 제어는 사용자 보고로 중지 동작과 제어 중 다른 리소스 제어 차단을 확인했다. 첨부 화면은 RDS 중지 진행 상태이며 최종 stopped 도달·시작·오류 상황 등의 실환경 검증은 보류했다. 에이전트의 새 AWS 호출은 없다.

## 1. 현재 단계

**Phase 1 / Day 1 완료, Day 2 개별 제어 구현·로컬 검증 완료, 실제 확인 대기.** 로컬 그룹 삭제는 구현·자동 검증을 마쳤고 삭제 버튼·확인창·화면 전환은 사용자 보고상 이상 없다. 기존 설계대로 그룹에 등록된 EC2 시작·중지·재부팅과 RDS 시작·중지, 확인 모달·단일 실행·목표 상태 대기·전역 진행·제한시간 설정을 구현했다. 중지 동작과 제어 중 다른 리소스 제어 차단은 사용자 보고로 확인했으며, 나머지 실환경 검증은 사용자 요청으로 보류했다. 그룹 순차 제어와 Phase 2는 시작하지 않았다.

아래의 `완료`는 해당 범위의 **코드 구현 상태**를 뜻한다. 빌드·Mock·실제 AWS 검증 결과는 §4에서 별도로 판정한다. 일부만 구현했거나 단계 완료 조건이 남으면 `진행 중`, 핵심 코드가 없으면 `미완료`로 표시한다.

## 3. 현재 코드에 구현된 주요 기능

- 2026-10-21 구조 정리: 최상위 Views(하위 Dialogs, Styles), ViewModels, Models, Services(하위 Aws, Groups, Persistence, Dialogs), Commands, Navigation으로 이동했다. 기존 클래스·메서드·기능 로직·JSON 형식은 유지하고 네임스페이스·XAML 리소스 경로·테스트 참조만 수정했다.

- WPF 다크 테마 셸, 공통 `ResourceDictionary`, MVVM 내비게이션, 저장 그룹 카드와 로컬 구성 상세 화면.
- AWS 연결 관리 화면의 프로필 선택·목록 다시 읽기·연결·해제·수동 상태 확인. 프로필 선택만으로 AWS에 자동 연결하지 않는다.
- 프로필 전환·연결 해제 확인은 앱 다크 테마 모달로 표시한다. 사용자가 취소하면 연결 변경을 진행하지 않는다.
- AWS SDK for .NET의 로컬 프로필 조회와 STS `GetCallerIdentity` 호출 경계. 성공 시 프로필명·전체 계정 ID·Caller ARN·마지막 확인 시각을 전역 상태와 화면에 표시하도록 구현했다.
- STS 인증 성공 시 같은 프로필 자격 증명 세션을 활성화하고, 세션의 EC2/RDS/S3 읽기 API로 조회하도록 구현했다. 연결 세대가 바뀐 뒤 도착한 예전 조회 결과는 화면에 반영하지 않는다.
- `그룹 만들기`의 5단계 마법사에서 그룹명·연결 계정·리전, 선택 서비스만 조회, EC2/RDS/S3 체크 선택과 중복 등록 안내, EC2/RDS 혼합 시작 순서, 최종 검토·등록을 제공한다. S3는 그룹 리전과 다른 버킷도 선택하며 버킷 실제 리전을 저장한다. 조회 실패 시 이전 목록을 보존하고 조회 중 이탈하면 늦은 결과를 폐기한다.
- 그룹 등록 전 이탈 및 빈 그룹 등록 확인 모달, 등록 성공 전용 화면, 저장 그룹 대시보드 카드와 읽기 전용 구성 상세를 구현했다.
- 그룹 대시보드 카드에 EC2/RDS 실행·중지·기타 개수, S3 버킷 조회 가능 수, 마지막 정상 조회 시각을 표시한다. 카드·전체 수동 갱신과 앱 실행 중 30초 자동 갱신을 제공한다. 그룹 상세는 등록 자원별 현재 상태를 표시한다.
- 저장 그룹 계정과 활성 계정이 다르거나 미연결이면 AWS 조회를 실행하지 않고 안내한다. 서비스별 조회 실패는 다른 서비스의 결과와 이전 정상 상태를 유지하며, 인증 만료 시 재연결을 요구하고 늦은 이전 연결 결과는 폐기한다.
- 프로필 전환·해제 확인, 새 프로필 인증 실패 시 기존 연결 유지, 인증 무효 시 재연결 필요 표시, 비동기 명령과 취소 토큰 전달.
- 마지막 **선택** 프로필명과 그룹 구성을 하나의 사용자별 JSON 설정에 저장·복원한다. 그룹에는 GUID, 이름, 계정 ID, 고정 리전, 등록 자원·순서·프로필 이름을 저장하며 인증 비밀 값은 저장하지 않는다. 손상된 설정은 시작 시 오류로 처리하고 덮어쓰지 않는다.

- 로컬 그룹 삭제: 그룹 상세 확인 모달, 삭제 중 중복 명령 차단, 저장 실패 시 기존 그룹 유지, 저장 성공 후 대시보드 이동과 카드/상태 제거. AWS 미연결·계정 불일치와 무관하게 동작하며 AWS API를 호출하지 않는다.

- Day 2 개별 제어: 그룹 상세 EC2/RDS/S3 탭·이름/식별자 검색·선택 상세·GridSplitter 및 제어 확인 모달. 등록 자원·계정·연결 세대를 서비스에서 재검증하고 EC2/RDS 상태를 직접 조회한 뒤 명령한다. S3 제어 없음.
- 앱 전체 동시 제어 1건, 화면 이동 중 실행 유지, 제어 중 연결 전환/해제/재확인·그룹 삭제 차단, 종료 경고, 셸 하단 진행·최근 결과 5건을 구현했다. 영구 이력은 아직 없다.
- 사용자 확정값: EC2 상태 5초·RDS 15초 확인, 제한시간 EC2 1~60분(기본 10분)·RDS 1~120분(기본 30분). 설정 화면에서 확인 후 JSON 저장하며 진행 중 작업에는 기존값을 유지한다.
- EC2 재부팅은 사용자 합의대로 요청 접수만 확인하고 완료 미확인으로 표시한다. 시작·중지는 실제 목표 상태를 확인한다. 명령 자동 재전송 없음, 실패·시간 초과 후 제한된 읽기 재조회만 시도한다.

## 5. 발견된 문제와 미해결 사항

- **개별 제어 실환경 부분 확인·나머지 보류:** 사용자 중지 동작·다른 리소스 제어 차단 확인을 반영했다. 첨부 화면은 중지 진행 중이므로 최종 stopped/완료 표시는 미확인이다. 시작·재부팅·오류 상황·확인 취소·화면 이동·연결/삭제/종료 차단·제한시간 설정의 개별 실환경 검증은 사용자 요청으로 추후 진행한다. 그룹 순차 제어와 남은 작업 취소는 미구현이다.
- **그룹 삭제 사용자 확인:** 삭제 버튼·확인창·화면 전환은 문제없어 보인다고 보고했다. 취소·재실행 등 세부 항목별 실제 조작 여부는 별도 미확인이며 로컬/Mock 검증은 통과했다.
- **조회 실패 실환경 미확인:** 권한·통신 오류와 늦은 응답은 모의 응답으로 확인했다. 실제 AWS 권한이나 네트워크를 변경하는 수동 검증은 수행하지 않았다.
- **새 그룹 세부 조작 검증 범위:** 사용자는 수정된 체크박스, 그룹 등록·복원, 이탈·중복 방지 및 연결 확인창이 문제없어 보인다고 보고했다. 빈 그룹 생성은 추가 확인했다. 표 정렬 중 선택 유지와 시작 순서 드래그/버튼 각각의 조작은 별도 미확인이다.
